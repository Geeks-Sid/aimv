# Architecture Audit — 2026-10-04

## Scope

This audit reviewed classification, batch processing, organization rules, folder
discovery, movement logging, undo, indexing, provider usage tracking, and test coverage.

## Baseline Findings

1. `cmd_batch` processed files sequentially; it had no worker pool or batch request.
2. `SmartMover` fused extraction, prompting, response parsing, interaction, folder
   creation, movement, logging, and indexing in one Module.
3. A raw directory snapshot was injected into prompts; there was no semantic taxonomy.
4. The seven Rules provided useful hints but could not represent hundreds of destinations.
5. Provider output could supply arbitrary absolute paths, subfolders, and filenames.
6. Dry-run could create directories before the dry-run check.
7. Shared API usage accounting and JSON persistence were not safe for concurrent workers.
8. Batch success meant only that no exception escaped, not that a file moved or stayed.
9. New folders did not update the saved template used by later classifications.
10. Tests did not cover `SmartMover`, batch classification, provider decisions, path
    confinement, or concurrency.

## Deepening Opportunities Applied

### Taxonomy Catalog Module

The Taxonomy Catalog Interface now loads 332 leaf Buckets, exposes bounded hierarchy
levels, resolves Bucket IDs, validates the tree, materializes readable folders, and owns
Folder Metadata. It also retrieves a Candidate Set for the optional generative fallback.
The Module gives callers leverage without exposing YAML traversal, ranking weights, path
construction, or metadata persistence. Taxonomy knowledge now has locality in
`aimv/taxonomy/`.

### Classification Module

The Classification Interface accepts a file and returns a typed immutable Classification
Plan. Its implementation owns Evidence preparation, Rule refinement, the complete Area →
Category → Bucket Decision Path, fallback Candidate Set formatting, strict schemas, and
validation. The provider adapter remains at a real seam because OpenRouter Jev, local or
self-hosted Laya, Google, and OpenAI-style providers are supported.

### Batch Module

The Batch Interface accepts ordered file paths and returns typed outcomes. Its
implementation owns bounded scheduling, partial failures, stable ordering, and progress.
Classification is parallel; mutation is not.

### Organization Commit Module

The Organization Commit Interface consumes a Classification Plan. Its implementation
owns confidence policy, confirmations, safe names, Managed Root confinement, year/month
routing, collision avoidance, movement, rollback attempts, logging, and indexing.

## Deletion Test

- Deleting the Taxonomy Catalog would spread identity, search, paths, and metadata back
  across prompts, CLI handlers, and filesystem code.
- Deleting the Classification Module would spread extraction and provider schema details
  across single-file and batch callers.
- Deleting the Batch Module would move concurrency, ordering, and error accounting into
  the CLI.
- Deleting the Organization Commit Module would duplicate mutation invariants in every
  caller.

Each Module therefore hides meaningful complexity behind a smaller Interface.

## Verification Added

- Taxonomy breadth and structural validation.
- Semantic candidate retrieval.
- Hidden metadata at root, Area, Category, Bucket, year, and month levels.
- Installed metadata alias round-trips.
- Full-taxonomy typed-decision traversal using bounded 16-, 5–8-, and 4-option choices.
- Human-readable final folder routes in Jev/Laya choice criteria.
- Typed decision and schema-enum validation.
- Filename traversal and extension-change rejection.
- Non-mutating dry-run behavior.
- Year/month routing and movement.
- Actual concurrent classification with ordered commits.

## Remaining Opportunities

1. Migrate the JSON file index to SQLite/FTS when catalogs grow beyond modest personal
   collections or multi-process writers are required.
2. Add provider contract tests against recorded Responses and Google payloads.
3. Add evaluation fixtures measuring complete hierarchical Jev/Laya placement and
   generative fallback top-candidate recall on a representative private corpus.
4. Add startup reconciliation for the rare case where both persistence and filesystem
   rollback fail because another process changes a path mid-commit.
5. Deprecate the legacy organization template after a compatibility window; it is no
   longer authoritative for managed destinations.
